# Entrega do projeto na DIO

**Autor:** Anderson Junior  
**Bootcamp:** Santander - Cibersegurança do Zero à Prática  
**Repositório:** https://github.com/Anderson0100/dio-kali-medusa-lab

O projeto reúne README, relatório, procedimentos, scripts, wordlists e 13 prints originais. O envio do endereço na plataforma DIO precisa ser feito pelo autor.

## Entregar

1. Abra o [repositório](https://github.com/Anderson0100/dio-kali-medusa-lab) e confira o README e o [relatório](03-relatorio.md).
2. Na DIO, abra o desafio correspondente no bootcamp e clique em **Entregar Projeto**.
3. Cole o endereço:

```text
https://github.com/Anderson0100/dio-kali-medusa-lab
```

4. Revise a descrição abaixo, cole-a no campo correspondente e conclua a entrega.

> Projeto de Anderson Junior para o bootcamp Santander - Cibersegurança do Zero à Prática, da DIO. Executei testes de dicionário em FTP com Medusa e no DVWA Low com Python, além de enumeração SMB e uma rodada de password spraying com Medusa. Validei o login FTP, a resposta do formulário web e a identidade SMB retornada pelo servidor. Organizei comandos, wordlists, 13 capturas originais e um relatório com as dificuldades encontradas. As evidências do DVWA mostram uma tentativa recusada, o acesso confirmado no navegador e sucesso na terceira tentativa automatizada. As medidas de prevenção são recomendações, sem aplicação ou reteste.

A publicação não equivale à aprovação pela DIO. Confira os critérios do desafio. Não é necessário repetir os testes nem manter as VMs ligadas para entregar o link.

## Baixar e acrescentar arquivos

Use **Code → Download ZIP** no GitHub e **Extrair tudo** no Windows, ou clone:

```bash
git clone https://github.com/Anderson0100/dio-kali-medusa-lab.git
cd dio-kali-medusa-lab
```

Os prints selecionados de FTP, DVWA e SMB já estão em images/ e incorporados ao relatório. A [seleção das evidências](05-evidencias.md) registra nomes de origem, legendas e critérios. Para futuras atualizações, preserve o conteúdo dos arquivos e mantenha os links e o manifesto coerentes.

A interface de upload do GitHub não aplica as regras do .gitignore. Revise arquivos antes de publicar; não envie cookies, tokens ou logs sensíveis. Preserve logs brutos em local privado. Você pode desligar as VMs normalmente pelo sistema convidado ou via ACPI, mantendo os discos para consulta posterior.
